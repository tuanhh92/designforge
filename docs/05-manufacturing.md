# 05 — Manufacturing package & production drawings

Everything here is computed from the **PartGraph** in `worker-core` (Linux, pure Python). None of it waits on SketchUp.

```
PartGraph ──► CutlistService ──► CutList ──► Nester ──► NestLayout ──► CncPostProcessor ──► programs
     │              │                             │
     │              └──► EdgeBandService          └──► sheet counts ─┐
     ├──► BomService (sheets, bands, hardware, consumables, labour) ◄─┘ ──► costing
     ├──► DrawingService ──► DrawingSet (PDF / DXF / SVG)
     ├──► LabelService ──► part labels (PDF, QR = version_id + part_key)
     └──► PackageService ──► production.zip
```

## 1. Cut list

1. Take every `Part`; compute **cut size** = finished − (band thickness + pre-mill) on banded edges (already in the PartGraph; recompute here as a cross-check — mismatch is a bug).
2. Group identical lines by `(material, thickness, cut_length, cut_width, grain, edge_band, operation signature)` → `qty`. Machining signature matters: two "identical" gables mirrored for left/right hinge holes are **not** the same CNC program.
3. Assign `label_code` = `{design_short}-{version_no}-{line_no:03d}` (printed on labels, nesting sheets, drawings).
4. Exports: JSON (API), CSV (generic), XLSX (formatted, with totals), and **OpenCutList-compatible** / CutList Optimizer CSV columns so shops can drop it into tools they already use.

## 2. Edge banding

Per edge-band code: Σ edge lengths + per-edge waste allowance (rule pack, typically 30–50 mm per edge) → metres; rounded to roll size in BOM.

## 3. BOM & costing

| Category | Source | Qty rule |
|---|---|---|
| Sheet | Nesting result | sheets used (or m² × waste factor if nesting disabled) |
| Edge band | §2 | metres → rolls |
| Hardware | `hardware_placements` + connectors from `joints` (minifix bodies + bolts + dowels) + shelf pins | pcs, rounded to pack size |
| Consumables | rules: glue per joint, screws per back, etc. | estimate |
| Labour | rules: minutes per part / per edge / per drilling op / per assembly | hours |

Prices from org price list → `bom_lines.total_minor`; cost roll-up drives a **quote** (V1 feature: "Quote PDF" for designers selling to clients).

## 4. Nesting (sheet optimisation)

- MVP: **guillotine/MaxRects** rectangular bin packing (`rectpack` library, or own implementation for guillotine-only — panel saws need guillotine cuts; CNC routers don't). Respect grain (no rotation when `grain != none`), kerf (rule pack, e.g. 4 mm saw / 6–12 mm router bit), sheet trim.
- Strategy: run 3–5 heuristics (sort by area/longest side/width; best-short-side-fit vs best-area-fit), keep best yield. Deterministic seeds.
- Output: `nest_layouts` rows + nesting PDF sheets (one page per sheet, label codes printed on parts) + DXF per sheet for routers.
- V2: offcut inventory (reuse remnants ≥ configurable size), true-shape nesting for non-rectangular parts.

## 5. CNC data

### MVP: generic DXF per part (works with most CAM: Alphacam, Aspan, Vectric, BiesseWorks DXF import, woodWOP DXF import)

Layer naming convention (configurable per org in V1 — **every shop has its own**):

| Geometry | Layer |
|---|---|
| Part outline | `OUTLINE` (or `CUT_18` = through cut 18 mm) |
| Vertical drill | `DRILL_V_D{dia}_Z{depth}` e.g. `DRILL_V_D35_Z13`, `DRILL_V_D5_Z13` |
| Horizontal (edge) drill | `DRILL_H_{edge}_D{dia}_Z{depth}` e.g. `DRILL_H_W1_D8_Z30` |
| Groove | `GROOVE_W{width}_Z{depth}` (polyline centreline) |
| Pocket | `POCKET_Z{depth}` (closed polyline) |
| Face B (other side) ops | suffix `_B` or separate DXF `{label}_B.dxf` |
| Text | `LABEL` |

Generated with **ezdxf**: R2010, units = mm (`$INSUNITS=4`), origin at part's front-left-bottom (machine zero conventions vary: configurable `origin_corner`).

### V1/V2: native dialects behind `CncPostProcessor`

| Dialect | Machine family | Format |
|---|---|---|
| `homag_mpr` | Homag / Weeke (woodWOP) | `.mpr` text |
| `biesse_bpp` | Biesse (bSolid/BiesseWorks) | `.bpp` |
| `scm_xxl` | SCM (Xilog) | `.xxl` |

Each needs a real customer machine to validate. Never ship a dialect without a test cut on actual hardware — a wrong Z depth breaks a tool or a part. Include a "dry run / simulation" PDF showing every operation per face.

## 6. Production drawings workflow

**Decision: drawings are generated by our own `df_drawings` from the PartGraph, not from SketchUp/LayOut.** Reasons: deterministic, Linux, fast (seconds), full control of dimensioning standards, and no dependency on the geometry farm. (LayOut via SketchUp is a V2 "designer presentation" option, not the shop drawing source.)

### Pipeline

```
PartGraph
  └─ 1. View generation      orthographic projections of part AABBs (panels are boxes ⇒ exact & trivial):
                              front elevation (doors on), front elevation (doors off / interior),
                              plan, side section through each section, isometric (from glTF render)
  └─ 2. Hidden-line removal  painter's algorithm on axis-aligned boxes (sort by depth, clip polygons with shapely)
  └─ 3. Dimensioning         rule-based: overall W/H/D chains, section widths chain, compartment heights chain,
                              shelf positions (32 mm grid), door/drawer front sizes; avoid collisions via
                              dimension-line stacking offsets (8 mm steps at 1:20)
  └─ 4. Annotation           part balloons → label_code; material legend; edge-band legend (symbols per edge);
                              hardware callouts (hinge positions, slide lengths)
  └─ 5. Part drawings        one per unique cut-list line: 2D part with all operations per face, hole tables
                              (x, y, Ø, depth, face), edge band marks, grain arrow
  └─ 6. Sheet layout         title block (org logo, client, project, design, version, date, scale, sheet n/N,
                              approved-by), auto-scale to paper (A3 default: 1:10 / 1:20 / 1:25), revision table
  └─ 7. Render               SVG (source) → PDF (cairosvg or reportlab) ; DXF (ezdxf) with layers per entity type
  └─ 8. Assemble             combined PDF + individual sheets; register artifacts; drawing_sheets rows
```

### Drawing set contents (MVP)

1. General arrangement: iso render + overall dims + material/finish schedule
2. Elevations: front (doors on), front (interior), side section per section
3. Plan
4. Part drawings (one per unique part with machining)
5. Hardware schedule (with positions)
6. Cut list & BOM tables
7. Nesting sheets (optional)

Standards: ISO 128 line types, dimension text 2.5–3.5 mm on paper; units mm; third-angle (default) or first-angle projection selectable per org (EU shops often expect first-angle — make it a rule-pack setting).

### Verification gates (automated, block the package if failing)

- Every part appears in exactly one cut-list line and one part drawing (or an "undrilled parts" table).
- Sum of section widths + divider thicknesses == inner width (re-derived from drawing geometry).
- Every drill op lies within its part and ≥ min edge distance (rule pack).
- No two holes from different hardware overlap on the same face.
- DXF re-import (ezdxf) round-trip check: outline bbox equals cut size.

## 7. Manufacturing workflow (shop view)

```
Designer approves spec ─► package generated ─► Shop lead reviews (production tab)
   ─► "Release to shop" (freezes version, audit) ─► download CNC + labels + nesting
   ─► cutting (saw/CNC) ─► edge banding ─► drilling (if not on CNC) ─► assembly (assembly sheet + hardware schedule)
   ─► QC checklist ─► delivery/installation
```

V1 adds: per-part status via label QR scan (cut / banded / drilled / assembled), so DesignForge becomes the shop's lightweight MES — this is the retention hook for manufacturers.
